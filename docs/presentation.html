1. Introduction

Motivation & Problem Definition: Why RouteWise?

Opaque Fuel Economics
  • Commercial apps (Google Maps, Waze) treat fuel as an invisible or static parameter.
  • Drivers cannot input their exact vehicle mileage (km/L) or current fuel prices (₹/L).
  • Users cannot evaluate exact rupees saved between alternative routes.
Ignored Urban Deceleration
  • Standard distance/mileage formulas ignore stop-and-go energy losses.
  • A route with 30 city turns consumes up to 35% more fuel than highway cruising.
  • Lack turn-density and road hierarchy feature engineering.
Zero Carbon Accountability
  • Rising climate awareness demands visibility into trip emissions.
  • No quantitative metrics showing kilograms of CO2 produced per trip.
  • No conversion into tangible offset metrics like required tree-days.

4. AI/ML Formulation

Mathematical Modeling: Predictive Fuel & Traffic Multipliers

1. Predictive Fuel Consumption Formula
  • Base Fuel: Distance (D) / Mileage (M)
  • Turn Density Metric (δ): Total Maneuvers / Distance (km)
  • Road Hierarchy Factor (ρ):
    • δ ≥ 0.4 turns/km → ρ = 1.08 (+8% urban stop-and-go penalty)
    • δ < 0.1 turns/km → ρ = 0.96 (-4% highway cruising bonus)
  • Time-of-Day Traffic Multiplier (Ct):
    • Morning Peak (08:00–10:00): Ct = 1.18 (+18%)
    • Evening Peak (17:00–20:00): Ct = 1.22 (+22%)
    • Night Off-Peak (23:00–05:00): Ct = 0.95 (-5%)
  • Final Formula: F_predicted = (D / M) × Ct × ρ
  • Fuel Cost (₹): F_predicted × Fuel Price (P)
2. IPCC Carbon Footprint Model
  • Scientific Basis: Intergovernmental Panel on Climate Change (IPCC).
  • Petrol Combustion: 2.31 kg CO2 per Litre
  • Diesel Combustion: 2.68 kg CO2 per Litre
  • Trip Carbon Output: CO2 (kg) = F_predicted × Emission Factor
  • Tree Offset Metric:
    • 1 mature tree absorbs ~21.77 kg CO2/year (0.0596 kg/day)
    • Tree Days Offset = CO2 (kg) / 0.0596 kg/day
  • Multi-Objective Badges:
    • ECO-FRIENDLY (Lowest fuel and carbon)
    • FASTEST (Least transit duration)
    • BALANCED (Optimal trade-off)

5. DBMS Normalization

Database Management Systems: 3NF Relational Architecture

Relational Schema (4 Tables)
  • users: user_id (PK), email (UK), password_hash, name, created_at.
  • fuel_settings: setting_id (PK), user_id (FK), vehicle_mileage, fuel_price, fuel_type.
  • search_history: search_id (PK), user_id (FK), source_name, lat/lng, dest_name, lat/lng.
  • routes: route_id (PK), search_id (FK), distance, duration, fuel_cost, co2_emissions, badge.
3NF Normalization Proof
  • 1NF (Atomicity): Atomic columns; lat and lng split into discrete float columns.
  • 2NF (No Partial Dependency): All non-key attributes depend fully on whole primary keys.
  • 3NF (No Transitive Dependency): User vehicle preferences stored in fuel_settings, eliminating redundant duplication in search logs.
Referential Integrity & Speed
  • ON DELETE CASCADE: Deleting a user cleans up settings and search logs automatically without orphaned child rows.
  • B-Tree Indexes: Foreign keys indexed (idx_fuel_user, idx_search_user, idx_route_search).
  • Reduces search history lookup from O(N) to O(log N).

6. Live Query Tool

DBMS Query Inspector: Live Relational JOIN & Analytics

Complex Multi-Table SQL JOIN
SELECT u.name, COUNT(DISTINCT sh.search_id) AS trips_planned, COUNT(r.route_id) AS routes_evaluated, ROUND(SUM(r.distance), 2) AS total_distance_km, ROUND(SUM(r.estimated_fuel_cost), 2) AS total_fuel_cost_inr, ROUND(AVG(r.duration), 1) AS avg_duration_mins, ROUND(SUM(r.co2_emissions), 2) AS total_co2_kg FROM users u INNER JOIN search_history sh ON u.user_id = sh.user_id INNER JOIN routes r ON sh.search_id = r.search_id GROUP BY u.user_id, u.name;
Academic & Evaluator Value
  • Direct On-Screen Execution: Evaluators can execute live SQL queries directly inside the application UI on the Dashboard page.
  • Aggregates & Analytics: Demonstrates real-time COUNT, SUM, AVG, and GROUP BY execution across 3 relational tiers.
  • Transparency: Eliminates the 'black-box' perception of web databases by displaying raw result tables and timing telemetry.
  • Parameterized Execution: Prepared statements protect against SQL injection.

8. Cyber Security

Cyber Security: Defense-in-Depth & OWASP Top 10 Mitigation

A01: Broken Access Control

Stateless HMAC-SHA256 JWT tokens with 24h expiry; authMiddleware.js verifies identity.

A02: Cryptographic Failures

Bcrypt hashing with 10 salt rounds (1,024 iterations); unique salt blocks rainbow tables.

A03: Injection Attacks

100% Parameterized SQL queries using placeholder tokens (?); prepared statements neutralize SQL injection.

A04: Insecure Design & DoS

Express Rate Limiting: 20 req/15min on auth endpoints; 100 req/15min on routing APIs thwart brute force.

A05: Security Misconfiguration

Helmet.js sets strict Content-Security-Policy, X-Frame-Options: DENY (clickjacking), and nosniff.

A07: Cross-Origin Risks

Strict CORS origin whitelisting permits requests only from authorized frontend domains.
